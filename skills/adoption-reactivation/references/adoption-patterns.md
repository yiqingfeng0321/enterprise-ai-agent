# Adoption intervention patterns

Use the thresholds below as routing signals, not proof of root cause.

| Observed signal | Validate first | Suitable first experiment | Leading measure |
|---|---|---|---|
| Incomplete onboarding | Tenant, permissions, integration, security, owner | Route to deployment recovery | Verified onboarding milestone |
| Active-seat ratio below 35% | Eligible seats, access, target cohort, workflow relevance | Narrow cohort activation sprint | Weekly active-seat ratio for target cohort |
| Usage decline of 15% or more | Metric definition, seasonality, workflow-level decline | Workflow recovery session and friction review | Repeat workflow completions |
| Zero or one champion | Role coverage and manager sponsorship | Champion enablement plan | Active champions and coached users |
| Workshop already failed | Memory outcome and reason | Change the lever, cohort, or blocker | New behavior tied to the changed hypothesis |

## Experiment contract

Define:

- one supported workflow and target cohort;
- the observed baseline and time window;
- a desired repeatable behavior;
- one accountable owner and a dated checkpoint;
- an observable success threshold;
- a stop, change, or scale decision after measurement.

Do not use logins alone as proof of workflow adoption. Do not promise churn reduction. Do not expand the experiment until the target cohort meets the stated criterion.

## Example

Weak: “Provide more training to improve engagement.”

Strong: “After access is verified, the Adoption Consultant will run two claims-review sessions for the supplied operations cohort. Compare weekly completed claims-review workflows with the current baseline after 14 days; change the intervention if repeat use does not improve.”
